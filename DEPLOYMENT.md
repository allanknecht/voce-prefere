# Deployment: Render (free) + Neon (free Postgres)

Everything below works on free plans: Render's free web service (Docker) and a free Neon Postgres database.
No Redis, no disk, no background worker.

## 1. Create the database (Neon)

1. Create a project/database in Neon and copy the **connection string** (it looks like
   `postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require`).
2. Keep it secret; it goes into Render as `DATABASE_URL` (never into the repo).

Neon scales compute to zero when idle; the first query after a pause can take a moment
(`connect_timeout` is 15 s in `config/database.yml`).

## 2. Create the web service (Render)

1. Push the repository to your own Git host (GitHub/GitLab).
2. In Render: **New +** → **Blueprint** (uses `render.yaml`) or **Web Service** with runtime **Docker**, plan **Free**.
3. Set the environment variables:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | the Neon connection string |
| `SECRET_KEY_BASE` | generated by the blueprint (or `bin/rails secret`) |
| `ADMIN_SECRET` | generated by the blueprint (or `openssl rand -hex 32`); at least 16 characters |

(`MODERATION_BLOCKLIST` / `MODERATION_NAMES_BLOCKLIST` are no longer used: there is no automatic filter. If they are still set on Render they are ignored and can be deleted.)

`RAILS_ENV=production` is set by the Dockerfile. Health check path: `/up`.
There is no `RAILS_MASTER_KEY` and no `config/credentials.yml.enc`.

4. Deploy. On start the container runs `bin/rails db:prepare` (creates/migrates the tables in the Neon database).
   To load the 22 example options once, open a Render shell and run `bin/rails db:seed`
   (the free plan may not offer a shell; alternatively run `DATABASE_URL=... bin/rails db:seed` from your machine).

The app **refuses to boot in production** when `ADMIN_SECRET` is missing, shorter than 16 characters or equal to
the old placeholder, so a misconfigured deploy fails visibly instead of running with a guessable password.

## 3. Free tier behaviour

- The service **sleeps after 15 minutes without inbound traffic**; the next request wakes it up and takes roughly
  30–60 seconds. That is expected on the free plan.
- Do not add pingers to keep it awake: they add an outside party to your traffic, and the free instance hours are limited anyway.
- No persistent disk: nothing is written locally. All data lives in Postgres.

## 4. Admin

Go to `https://<your-service>.onrender.com/admin/login` and enter `ADMIN_SECRET` in the form.
Query-string logins (`?secret=`) are not supported. The admin cookie is `Secure`, `HttpOnly`,
`SameSite=Strict`, `Path=/admin`, valid for 1 hour.

## 5. Local production test

```bash
export RAILS_ENV=production SECRET_KEY_BASE=$(bin/rails secret) ADMIN_SECRET=$(openssl rand -hex 24) \
       DATABASE_URL=postgresql://user:pass@localhost/voce_prefere
bin/rails assets:precompile db:prepare
bin/rails server            # force_ssl is on: send `X-Forwarded-Proto: https` (as Render's proxy does)
```

## 6. Docker

```bash
docker build -t voce-prefere .
docker run -d -p 3000:10000 \
  -e SECRET_KEY_BASE=$(openssl rand -hex 64) -e ADMIN_SECRET=$(openssl rand -hex 24) \
  -e DATABASE_URL='postgresql://user:pass@host/db?sslmode=require' voce-prefere
```

Put a TLS-terminating proxy in front (Render does this for you); the app redirects plain HTTP to HTTPS and sends HSTS.

## 7. Post-deploy checklist

- [ ] `/` shows a pair (seed data loaded) and voting works
- [ ] Submitting an option works and lands in `/admin` when flagged
- [ ] `/admin/login` works with the form; `/admin?secret=...` does **not** log in
- [ ] `curl -sI https://<host>/` shows `content-security-policy`, `strict-transport-security`, `x-content-type-options`, `referrer-policy`, `permissions-policy`, `x-frame-options` and **no** `set-cookie`
- [ ] Render logs show `Started GET "/" at ...` with **no client IP**
- [ ] `/up` returns 200

## 8. Troubleshooting

- **Boot fails with "ADMIN_SECRET must be set"**: set a strong value (≥ 16 chars, not the placeholder).
- **`PG::ConnectionBad` / timeout at boot**: check `DATABASE_URL` (include `?sslmode=require` for Neon); retry after Neon wakes up.
- **"Requisição inválida" when voting**: the page was open for over 24 h (form token expired) or a proxy strips the
  `Origin` header; reload the page.
- **Rate limit stuck**: rows expire within an hour on their own.
